#### 为了让趋势线成立，先补了两张逐日序列表

票据要求「近 30 天趋势 + 环比箭头」，而当时各模块只落盘聚合值——一个 90 天的汇总数撑不起
一条折线。补法是**各模块各自落盘逐日表**（模块一 `daily_kpi.csv`，模块二
`daily_baseline_kpis.csv`），并新增 `python -m src.transport_optimize --daily-only`。

这里有个必须避开的坑：为补日表而重跑 `transport_optimize.run_all` 最省事，但 `run_all` 会
顺带重跑代表日的 30 秒启发式搜索并覆盖 `transport_kpi.json`。而带时限的搜索**同参数多次求解
不保证同解**（实测同一档出现过 876.15 / 870.16 km，相差 0.68%），那样 10/11 号票已发表的
里程、成本与 TCO 结论会被全部作废。故 `--daily-only` 只算日表、不碰优化结果，单测直接断言
「调用后 `transport_kpi.json` 的字节内容与 mtime 均未变化」。详见 ADR-0014。

顺带把 `run_all` 里那段 90 天循环抽成公开的 `daily_baseline_kpis()` + `summarize_all_days()`，
**全量汇总改为从日表再聚合**，不再自己跑第二遍循环——两处各算一次正是数字对不上的经典来源。
单测断言 `summarize_all_days(daily)` 与已发表的 `baseline_all_days` 逐字段相等。

#### 基建的五条设计取舍

1. **只有一组筛选器，永远在侧边栏**，不放进任何图表卡片里。四个控件：日期范围（预设 7/30/90 天
   + 自定义）、品类、配送区域、成本口径。
2. **「最近 N 天」锚在数据的最后一天（2026-08-29），不是今天。** 这是一个历史模拟窗口；按「今天」
   算会得到空区间，看起来像看板坏了。侧边栏直接把这行写出来。
3. **筛选器作用域如实声明，不假装全部生效。** 配送订单表没有品类字段，运输侧就吃不到品类筛选
   ——页面顶端用 `scope_note` 写明「本页生效的筛选器：日期范围、配送区域」，而不是把「全部品类」
   当成一个筛过的结果展示。
4. **读数缓存把文件 mtime 纳入缓存键。** 只按路径缓存的话，脚本重跑出新产品后页面会一直读旧数，
   那正是「看板数字与报告对不上」最常见的来源。现在产物一变自动重读，另留一个「刷新产物读数」
   按钮做显式兜底。
5. **缺产物就停下并列出补法，不回退到 0 或空图。** 一个显示「0」的看板比一个报错的看板危险得多：
   前者看起来像「今天没有异常」。`require_artifacts()` 直接列出缺哪个文件、该跑哪条命令，然后
   `st.stop()`。

#### 图表按配色规范实现，两处是硬约束而非偏好

配色用的是经**校验脚本**逐对判定过的八槽类别色板（相邻对 CVD ΔE ≥ 8、常视觉 ΔE ≥ 15，浅深两套
各自通过），槽位顺序本身就是色盲安全机制。两处按规范必须这么做：

- **绝不使用双 Y 轴。** 量纲不同的指标（%与元/单）一律拆成**各自一根轴**的小倍数图。双 Y 轴
  让两条曲线的相对位置变得任意，会凭空造出数据里没有的相关性。帕累托图的双轴问题留给 13 号票
  按同一原则处理。
- **每张图都配表格视图。** 浅色模式下青/黄/品红三槽对底色对比度低于 3:1，规范要求以「可见标签
  或表格视图」缓解——这是必需项。它同时满足「悬停提示只能增强，不能是读到数值的唯一途径」。
  另：单序列图不放图例（标题即序列名）+ 端点直接标数值；多序列图必须有图例。

配色未用彩虹色阶、未按值深浅给柱上色（那是把柱高在色相上再编码一遍）、状态色（good/warning/
serious/critical）始终配图标与文字、绝不拿来当第几个序列用。

#### 验收（按 spec 决策：手测，不写 UI 自动化）

- **首屏无报错**：服务端错误日志为空；四张卡片、四张趋势小图、预警清单、口径说明全部渲染。
- **筛选与卡片联动（端到端实测）**：默认「最近 30 天」→ 区间内运单 **3,146** 单、异常 **265** 单
  （8.42%），卡片为 库存准确率 **99.93%**、时间窗达成率 **85.62%**、满载率 **62.9%**、
  单均成本（纯电租赁）**42.14 元/单**。切到「最近 7 天」后区间变为 2026-08-23~08-29，运单降到
  **715** 单、异常 **73** 单（10.21%），卡片重算为 **99.95% / 84.43%**，环比对照自动切换为
  等长的前一区间。
- **环比语义正确**：成本类指标「下降=改善」，所以箭头方向与好坏判定分开（`Metric.is_good` 由

### 代码评审批次（2026-09-14，Standards + Spec 双轴）

两条轴**各自独立地**抓到了同一个真缺陷，它也是本票最值得记的一条：

1. **重构反而制造了「两处数字对不上」（最严重）。** 我把全量汇总改为从日表再聚合，但日表当时
   对每天的距离/成本各自 `round(2)` 后再求和，而旧的全量循环是整体求和后取整——实测
   **96,932.7 vs 96,932.6 km、424,589.16 vs 424,589.22 元**。这正是 ADR-0013 明令禁止的、
   我这一票开头刚花力气修过的那类失真，自己在重构里又犯了一次。
   **修法**：逐日值落盘时**不取整**（日表是数据产物，取整会丢信息），舍入只在发布口径（汇总）
   那一步做一次。改完实测逐字段完全相等，已发表的数字一个都不用动。

2. **守护这个不变量的测试是循环论证。** 原测试比较 `summarize_all_days(daily)` 与
   `kpi["baseline_all_days"]`，两边都出自**同一次 `run_all`**——所以上面那 0.1 km 的偏差它
   永远抓不到。**修法**：改为读**磁盘上已发表的** `transport_kpi.json` 与
   `daily_baseline_kpis.csv` 对账，一旦重新分叉立刻失败。教训写进 ADR-0014：
   **测试不能拿同一次运行的两个视图互相印证。**

3. **看板的缓存自动失效根本没生效。** 我把 mtime 塞进缓存键，但塞在了**内层** `_read_csv` 上，
   而公开 loader（`warehouse_daily()` 等）**无参数**——装饰在外层的 `st.cache_data` 缓存键恒定，
   内层根本不会执行，产物更新后页面照样读旧数。**修法**：去掉 19 个公开 loader 的外层装饰器，
   缓存只留在会收到 mtime 的原语上。**实测验证**：把日表最后一天的按时单清零 → 页面不重启、
   不清缓存，时间窗达成率卡片从 **85.62% 自动变为 82.88%**；还原后回到 85.62%。

4. **筛选器作用域被过度声称。** 页面原写「本页生效的筛选器：日期范围、配送区域」，但配送区域
   其实只作用于异常清单。**修法**：改为「日期范围作用于 KPI 卡片与趋势图；配送区域作用于异常
   预警清单；品类与运输侧无关」，把边界说到与实现完全一致。

5. **「每张图都配表格视图」这条自定硬约束没落实**：四张趋势图的 `chart_block` 都没传 `table=`。
   已为每张图补上各自的数据表，并在 `theme.py` 写明**调用方必须传 `table=`**，否则这条约束就是废话。

6. **配色校验的声称无法复核**：`theme.py` 原写「经校验脚本判定」但仓库内没有该脚本。已改为写明
   用哪个脚本、两条实际命令与实测数值（浅色 CVD 最差 9.1 / 常视觉 19.6，深色 8.4 / 19.3，
   浅色三槽对比度低于 3:1 故触发缓解规则），使结论可被他人重跑复核。

7. 其余修正：`components.py` 三处硬编码色值改用 theme token（否则「改色须重跑校验」的纪律失守）；
   `app.py` 副标题硬编码的「2026-06-01 ~ 08-29」改为由 `order_window()` 派生；成本口径的中文标签
   原本在三处各写一份字典，合并为 `kpis.MODE_LABELS` 单一定义；`inventory_accuracy(by="date")`
   补上 `book_value=0` 的防护（原先可能产生 `inf`）；台账「全量基线覆盖」行同步为新的函数名与
   「逐日不取整」的口径说明。

评审确认无误的部分：`write_daily_only` **确无副作用**（测试断言 `transport_kpi.json` 的字节内容
与 mtime 均未变化）；**看板层确无 KPI 公式重实现**，只复用模块一/二的产物列；`Metric.is_good`
把「箭头方向」与「好坏」解耦正确；`require_artifacts` 缺产物即停不显示 0；四张趋势图各自一根轴
无双 Y 轴、单序列无图例，与规范自洽；票据里引用的卡片与区间数字经独立重算**逐个吻合**。

**两条范围说明（评审提出、保留不改）**：① 侧边栏多了第四个「成本口径」下拉，超出 spec 列的三个
筛选器——保留理由：车队是 9 电/6 柴混编，「单均成本」不写计价模式就是个含糊数。② `data.py` 预置了
本票尚未调用的 loader（ABC 帕累托、逐趟明细、TCO、what-if 缓存、GeoJSON 等）——本票的定位就是
13/14/15 号票的基建，这些是它们的读数入口。

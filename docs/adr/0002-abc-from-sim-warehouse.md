# ABC 分类基于仿真仓出库行数，而非 Olist

需求文档 3.7 把「ABC 分类」列在 B 组（数据源 3.2 Olist）下，但同节 3.7C 的库位重排、3.6 实验一的「A 类近库位 vs 远库位」对照，都必须基于**同一套带库位坐标的 SKU**——而库位是仿真仓（3.1）独有的概念，Olist 的 product_id 没有库位、与仿真仓 500 个 SKU 也无对应关系。

我们决定：ABC 分类锚定在**仿真仓出库单的行数累计占比**（500 SKU × 90 天），算出 A/B/C 后直接驱动库位重排与仿真实验一。Olist 侧只算真实履约 KPI（真实准时交付率、延迟率按州/重量段/月份下钻），**不算 ABC**。文档中 ABC 的归属从 B 组移到 A 组。

## Considered Options

- 严格按字面用 Olist 算 ABC 再映射到仿真仓：两者 SKU 无对应，映射只能靠假设，污染严重。
- 两套都算：Olist 的 ABC 在本项目无任何下游消费者（不驱动重排、不驱动仿真），属为分类而分类，违背「不自行新增需求外功能」。

## Consequences

- 整条「ABC 分类 → 库位重排 → 仿真验证 → 拣货效率提升」的因果链同源、自洽、可复现。

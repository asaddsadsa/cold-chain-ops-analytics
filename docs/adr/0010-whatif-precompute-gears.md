# 改善页 what-if 的车辆数档位为 16 档离线预计算

3.9.4 要求「车辆数量 5–20 滑块重算 VRPTW、KPI 实时重算且无报错」。OR-Tools 单次求解上限 30 秒，若滑块每次拖动都同步求解，体验不可接受且易超时。

我们决定：**离线预计算 + 缓存切档**。数据层运行时对车辆数 5–20 共 16 档，各在代表日跑一次 VRPTW（每档 ≤30 秒，总计约 8 分钟，一次性），把每档的总里程、用车成本、时间窗达成率、满载率等结果缓存到 `data/processed/`；看板滑块仅从缓存读取对应档位、瞬时刷新。与 3.6 仿真实验档位预计算缓存的哲学统一。台账登记「what-if 车辆数档位为预计算结果，非实时求解」。

## Considered Options

- 滑块实时求解、时限压到 5 秒：解质量差且仍有数秒卡顿。
- 只预计算 5/10/15/20 四档：偏离「5–20」的字面要求。

## Consequences

- 一键复现的离线阶段变长约 8 分钟，换来看板侧零等待、零报错。
- 若用户在 what-if 中同时改「车辆数 + 其他重求解参数」，超出预计算网格的组合明确提示「需重跑预计算脚本」，不做隐式实时求解。

# 成本参数以文档锚点登记台账，URL 待实现期补齐

TCO 成本模型的参数（车型法规、司机工资、能源单价、购车/保险、租赁报价、货拉拉计价）需要「真实公开来源 URL 逐项登记」。但设计期实测：本机 WebFetch/WebSearch 被网络策略拦截，curl 仅白名单可达（相关站点只有首页可通、搜索不可用），无法在本会话可靠抓取可引用 URL。为编造 URL 而运行的检索工作流已被主动停止。

我们决定：以需求文档 3.4 给定的数值为**中位锚点**如实登记台账，来源栏标注「来源类别（公安部轻型货车规范 / 成都招聘市场 / 柴油电价公开行情 / 成都新能源租赁市场 / 货拉拉公开计价）+ URL 待实现期在可联网环境补齐 + 锚点登记日期」，数据类别统一登记为**情景假设**，并按要求做司机工资、油价/电价、租金三参数的低/中/高三档敏感性分析。结论稳健性由敏感性分析承载，不依赖单一 URL。

## Considered Options

- 由子代理强行逐站爬取：搜索被拦、反爬严重，产出必然是不可靠或编造的链接，触碰「数字真实」红线。
- 等用户提供 URL 后再登记：台账可以先以「待补」状态成立，不阻塞设计定稿；用户随时可补。

## Consequences

- 实现期（正常网络环境）必须回填每个参数的 URL 与检索日期，回填前台账中这些行保持「URL 待补」标记，报告引用这些数字时注明其情景假设性质。
- 这是「失败不伪装」纪律的执行示范：拿不到的外部事实显式标注，绝不静默编造。

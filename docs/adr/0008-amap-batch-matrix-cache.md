# 高德距离矩阵用「批量接口 + 永久缓存」消化配额不确定性

高德 Web 服务的具体逐接口配额数字已移到登录后的控制台（公开 flowlevel 页只写「配额请到 定价-基础服务配额说明 / 控制台-流量分析-配额管理 查看」，页面更新于 2024-07-15），公开页不再列数值，且本机网络策略屏蔽了部分文档站。因此无法、也不应凭记忆写死配额数字。

我们决定靠**设计**而非「赌配额够大」来保证矩阵能一次性建好：用高德距离测量接口 `/v3/distance`（type=1 驾车）的**批量能力**——单次请求传多个 origins 对单个 destination，一次同时返回里程与时间。构建「DC + ≤60 POI」共 61 节点的对称矩阵，按每个目的地发一次批量请求，约 **61 次调用**即可覆盖；加 POI 分页搜索约几十次，总计约百次量级。矩阵与 POI **永久缓存**到 `data/geo/`，只在首次构建时联网，之后所有运行直接读缓存。调用全程限速（间隔 ≥0.3 秒）、失败按 1/2/4 秒指数退避重试至多 3 次。

## 待实现期核实项

- `/v3/distance` 单次 origins 的批量上限（常见为 100，但**以实现期查证的高德接口文档为准**，不凭记忆写死）；若上限小于节点数则分多次请求。
- 个人开发者当前对距离测量 / 搜索 POI 的日配额与 QPS（实现期登录高德控制台「配额管理」页核实并记入台账，附检索日期）。

## Consequences

- 即便个人免费日配额较低，百次量级 + 永久缓存也几乎必然一天内建完；配额不确定性不再是阻塞。
- 他人无密钥时，用仓库预置的缓存矩阵即可复现全部下游结果（符合 3.3.4 与可复现纪律）；OSMnx 降级路径仅在缓存也缺失且无密钥时启用。

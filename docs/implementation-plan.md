# 实施计划（按阶段门禁拆解）

> 本文件是设计打磨会话（2026-09-13）的产出：需求理解确认 + 阶段任务清单 + 关键假设与风险。
> 配套文档：`CONTEXT.md`（术语表）、`docs/adr/0001–0010`（十条架构决策）、`data_sources_ledger.md`（台账草稿）。
> 实现期任何与本文件冲突的改动，先改 ADR 再改代码。

## 一、需求理解确认（摘要）

- **四层数据分类是最高原则**：真实观测（Olist、高德 POI/路网）/ 学术基准（Solomon）/ 过程仿真（SimPy、仿真仓表）/ 情景假设（配送订单、车辆参数、在途异常）。每个数字可溯源到台账，仿真绝不表述为真实观测。
- **模块边界**：6 个数据层（A 仿真仓表 / B Olist 清洗 / C 高德地理 / D 配送情景 / E Solomon 门禁 / F SimPy 仿真）→ 4 个交付模块（仓储分析 / 运输优化 / 看板 / PDCA 报告）+ 台账 + 单测。
- **已定的关键口径**（详见 ADR）：仿真校准锚定自家仿真仓、与 Olist 只做形状对照（0001）；ABC 分类基于仿真仓出库行数（0002）；VRPTW 代表日精算 + 贪心全量外推（0003）；节点=POI 需求聚合、单点一访、逐单判准时（0004）；成都场景=冷链城配、Olist 分布仅借形状（0005）；Python 3.14.6 + pandas 锁 2.3.3（0006）；PDF 用 headless Edge 实测方案（0007）；高德矩阵批量接口+永久缓存（0008）；成本参数文档锚点+URL 待补（0009）；what-if 车辆数 16 档离线预计算（0010）。
- **术语已钉死**：「真实准时交付率」（Olist，≤预计送达）≠「时间窗达成率」（配送，落在时间窗内）；驾驶舱 KPI 卡片显示后者。

## 二、阶段任务清单（门禁制）

### 阶段 0：工程骨架
- 任务：目录结构（data/{raw,warehouse,geo,delivery,processed}、src、pages、report、tests）、`src/config.py`（集中具名种子+全局参数）、`requirements.txt`（锁版本：Python 3.14 / pandas 2.3.3 / ortools 9.15 等已验证清单）、`.env.example`、`.gitignore`（排除 .env、raw 大文件、缓存矩阵之外的敏感物）、`archive/` 九表拷入 `data/raw/olist/`、README 骨架。
- 产出物：可运行的空骨架 + 依赖安装成功。
- 自测：`pip install -r requirements.txt` 在 .venv 全绿；目录与 3.12 一致。
- 门禁：依赖装齐、骨架完整 → 进阶段 1。

### 阶段 1：数据层 A/B（3.1 + 3.2，可并行 C）
- 任务 A：`src/gen_warehouse_data.py`——500 SKU/800 库位/90 天/日均 200–400 单，五张表，时间逻辑自洽，四埋点（A 类远库位、P03 高盘差、14–16 点低谷、收货晚到），质检摘要落盘 `data/processed/`。
- 任务 B：`src/olist_clean.py`——三段式获取（本地→kagglehub→报错指引）、清洗（delivered 过滤、时间矛盾剔除、邮编坐标聚合）、重量体积经验分布拟合保存、**真实延迟率统计**（供 D 层标定）、清洗前后行数对比。
- 自测：质检摘要中 4 个埋点的统计验证值显著（P03 差异率 vs 其他、14–16 点 vs 其余时段秒/行）；清洗损耗可解释；延迟率数值写入台账。
- 门禁：两脚本可重跑且种子固定输出一致 → 进阶段 2。

### 阶段 2：数据层 C/D（3.3 + 3.4）
- 任务 C：`src/geo_poi.py`（分页抓取 40–60 POI、限速≥0.3s、行政区分散、缓存）、`src/geo_matrix.py`（批量距离接口建 61×61 对称矩阵、指数退避、永久缓存；离线降级 OSMnx 路径）、`.env` 读 `AMAP_KEY`。
- 任务 D：`src/gen_delivery_data.py`——泊松订单、Olist 分布抽样重量体积、2 小时时间窗、R01–R08 聚簇片区（R07 埋高异常）、车辆表 15 台（柴油/纯电、3.4 成本参数从 config 读、全部登记台账）、在途轨迹与异常表（异常概率以 Olist 延迟率标定；周五/R07/雨天/低满载四埋点；温度 [2,8℃] 波动）、质检摘要。
- 自测：矩阵对称完整、POI 空间分散度达标；无密钥时用缓存可跑通下游；D 层质检摘要复现四埋点。
- 门禁：C+D 产物齐全且质检通过 → 进阶段 3。

### 阶段 3：数据层 E/F + 模块一（3.5 + 3.6 + 3.7）
- 任务 E：`src/solomon_validate.py`——从 UMA 镜像下载 C101/R101/RC101 + best-known（禁止凭记忆填数）、标准解析器、与 3.8 同构的 OR-Tools 建模、gap 计算。**gap>10% 门禁：排查并记录，不带病进阶段 4。**
- 任务 F：`src/warehouse_sim.py`——非齐次泊松到达（9–11、14–16 高峰）、实验一 ABC 分区 vs 原始库位、实验二人力 4/5/6 档，各 30 次重复报 95% CI，与 Olist 出库响应子段做形状对照（ADR-0001），结果预计算缓存。
- 任务一：`src/warehouse_kpi.py`——A 组仓内 KPI（库存准确率/收货及时率/拣货效率/履约时效/库容利用率/盘点差异率+P03 与 14–16 点下钻）、B 组 Olist 真实履约 KPI（准时/延迟率按州/重量段/月份下钻、reviews 交叉）、**ABC 分类（仿真仓出库行数口径，ADR-0002）**、C 组库位重排前后行走成本对比。
- 自测：每个 KPI 函数有单测正例；埋点在 KPI 输出中定量复现；每个 KPI 的手工算例单测通过；Solomon gap 记录在案。
- 门禁：**Solomon 门禁通过** + 模块一全部 KPI 落盘 + 单测绿 → 进阶段 4。

### 阶段 4：模块二（3.8）
- 任务：`src/transport_optimize.py`——基线贪心（真实路网矩阵）跑全 90 天；代表日（订单量最大日）OR-Tools VRPTW 精算（载重+容积+时间窗、30s 上限、目标=固定+里程成本）；需求聚合（ADR-0004）；前后对比表 + 两套 GeoJSON；周度异常分布（复现周五/R07 埋点）；单趟节省→月/年换算；TCO 双模式曲线+盈亏平衡里程+货拉拉对照+三档敏感性；what-if 车辆数 5–20 共 16 档预计算（ADR-0010）。
- 自测：对比表数字可追溯；GeoJSON 可渲染；敏感性三档输出齐全。
- 门禁：全部落盘 `data/processed/` → 进阶段 5。

### 阶段 5：看板（3.9）
- 任务：`app.py` 驾驶舱（KPI 卡片含**时间窗达成率**、环比、30 天趋势、异常预警）；`pages/` 仓储分析页（帕累托、分时段拣货效率、800 库位热力图、盘差 Top10、Olist 下钻、仿真实验+人力滑块）；运输分析页（Folium 优化前后切换、对比柱状图、满载率、异常饼图+周趋势、温控仪表、TCO 双曲线+外包对照表）；改善建议页（问题→动作→收益表，数字引用结果文件；what-if：车辆数/ABC 阈值/拣货员/动力模式+三档敏感性，全部读预计算缓存）。
- 自测：4 页无报错打开、全局筛选生效、滑块瞬时响应。
- 门禁：全部交互无报错 → 进阶段 6。

### 阶段 6：报告 + 部署整理（3.10 + 3.11 + README）
- 任务：PDCA 报告（P 3–5 个有数据支撑的问题各注数据类别；D 四项措施；C 每个数字引用 `data/processed/` 文件；A SOP+常态化监控）；`report/build_pdf.py`（headless Edge，降级显式告知，ADR-0007）；台账回填全部 🔶 项（URL、数值、日期）；README（一键复现五步、目录说明、截图、Streamlit Community Cloud 部署+st.secrets）；全局密钥泄露扫描。
- 门禁（= DoD 全项）：干净环境按 README 一键复现全部结果；台账无 🔶 残留（或显式标注阻塞原因）；单测全绿。

## 三、关键假设与风险

| # | 风险/假设 | 影响 | 应对（已定） |
|---|---|---|---|
| 1 | 本机网络白名单式受限：WebFetch/WebSearch 全拦，GitHub/SINTEF 不可达 | 外部事实核实困难 | 事实改用 Bash curl 白名单站核实；Solomon 走 UMA 镜像（已验证可达）；成本参数 URL 待实现期补（ADR-0009） |
| 2 | 高德个人配额数字公开页不可见 | 矩阵构建可能被限流 | 批量接口约 61 次调用 + 永久缓存（ADR-0008）；实现期登录控制台核实并记台账 |
| 3 | pandas 3.0 CoW 行为差异 | 清洗/KPI 代码隐性 bug | 锁 2.3.3（ADR-0006） |
| 4 | 仿真与 Olist 跨尺度 | KS 校准不可能通过 | 校准锚定仿真仓、形状对照（ADR-0001），验收口径随之解释 |
| 5 | 代表日节省率外推到 90 天的稳定性假设 | 月/年金额可信度 | 外推假设显式登记台账；贪心基线覆盖全量提供真实分母（ADR-0003） |
| 6 | 同店多单聚合后逐单判准时，时间窗外包络可能放宽个别订单的实际约束 | 时间窗达成率偏高 | 规则登记台账+ADR-0004；报告注明口径 |
| 7 | Olist 重量体积分布（巴西电商）与冷链城配货物的形状差异 | 抽样代表性 | 归类情景假设+台账声明借用性质（ADR-0005） |
| 8 | kagglehub 下载需 Kaggle 凭证 | 复现者无凭证 | archive 九表预置本地分支优先（设计决策 Q3） |
| 9 | weasyprint 缺 GTK | PDF 无法生成 | 已实测 headless Edge 方案转通（ADR-0007） |
| 10 | Solomon best-known 数值无法在线核实的环境 | 算法门禁基准缺失 | 禁止凭记忆；UMA known-best-results 下载解析，失败则报错给手动放置说明 |
